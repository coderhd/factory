# E12.2 Basic Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a small read-first static SPA from the Factory server that shows live Factory state (Work Orders, Observatory, approvals, interactions, scheduler), drills down `WO → Task → Attempt → trace → verification → evidence → decision`, and hosts an orchestrator chat panel whose mutations are authenticated.

**Architecture:** Three static assets (`index.html`, `app.js`, `styles.css`) under `src/factory/ui/`, read through a tiny caching loader (`assets.ts`) and served by the existing pure request handler (`createApiHandler`) on `GET /` and `GET /ui/*` — before the auth block, so the read-public GET boundary holds. The SPA is plain HTML/CSS/ES-module JS (no framework, no bundler, no build step); it reads the existing public GET routes and posts mutations (chat, answers, decisions, controls) with `Authorization: Bearer <token>` supplied by the operator at runtime.

**Tech Stack:** TypeScript on Bun; Bun's `Bun.serve` + `Request`/`Response` handler; Bun test; plain browser ES modules.

**Spec:** `factory-docs/2026-09-17-software-factory-design.md` §22 (Factory Client / Human UX) + §23 (Observatory: metrics + the `Work Order → Task → Attempt → trace → verification → evidence → human decision` chain); `factory-docs/implementation/operating-guide.md` §5/§8; `factory-docs/implementation/control-plane-auth.md`. Issue: GitHub #49 (parent epic #47).

## Global Constraints

- **Zero new runtime dependencies.** The SPA is plain HTML/CSS/JS — no framework, no bundler, no build step, no npm package. Only `src/factory/ui/` static files plus one Bun-builtins TS loader.
- **Server is the sole mutation authority** (spec §22 L1424–1428). The UI only calls the Factory API; it never writes state directly and never reads the store directly.
- **GET stays public; every mutating request requires the bearer credential** (E10.4 boundary, `server.ts:413`). The UI must send the token on non-GET and **never embed it** in any served asset.
- **Secrets are never logged, served, or committed.** The API key/token exists only as a runtime value (localStorage in the browser, `deps.auth` on the server).
- **Read-first, non-fabricating** (spec §23 L1474–1476, L1503): an empty Factory renders zeros and "no …" states, never invented data and never a crash.
- **Additive-only**: existing routes, status codes, and public signatures are unchanged.
- **Hermetic tests**: no network, no live model call, no real subprocess. `bun test` green; `sh scripts/check-tsc.sh` exits 0.

## Review Focus

The five input classes / failure modes most likely to bite a person using this software, each pinned to a test in the owning task:

1. **A UI that cannot load.** `GET /` and the assets must succeed **without a token** even when `deps.auth` is configured (the documented read-public boundary). → Task 1 test: unauthenticated `GET /` is 200 with `auth` set.
2. **A leaked credential.** No served asset may contain the token; the token is read from `localStorage` at runtime only. → Task 4 test: the served `app.js`/`index.html` contain no configured token value, and the loader never echoes a request header or token.
3. **An empty Factory.** No work orders / tasks / evidence / approvals must render zeros and "no …" text, not a crash or fabricated rows. → Task 2 test: empty store renders the zero/empty state for each panel.
4. **A failing or malformed API response.** A 500 (or non-JSON body, or a missing field) in one panel must not blank the page or throw unhandled — each panel degrades independently. → Task 2/3 tests: a failing panel renders an inline error while the others still render.
5. **An unauthenticated mutation.** Every UI affordance that mutates must be a real bearer-authorized API call; without a token the server must reject it (401), and the UI must not report success. → Task 4 test: mutation without a token → 401, with the token → 200.
6. **The orchestrator being unconfigured.** `POST /api/orchestrator/message` 503s when no orchestrator is composed; the dashboard must still load and the chat panel must say so. → Task 4 test: chat POST against a handler without an orchestrator → 503 and the dashboard endpoints still 200.

**Interfaces:**
- Produces (in `src/factory/ui/assets.ts`):
  - `export interface UiAsset { contentType: string; body: string }`
  - `export function uiAssetName(pathname: string): 'index.html' | 'app.js' | 'styles.css' | undefined`
    — `/` and `/index.html` → `'index.html'`; `/ui/app.js` → `'app.js'`; `/ui/styles.css` → `'styles.css'`; anything else → `undefined`.
  - `export async function loadUiAsset(name: 'index.html' | 'app.js' | 'styles.css'): Promise<UiAsset>`
    — reads `src/factory/ui/<name>` relative to this module (`new URL('./' + name, import.meta.url)` via `Bun.file`), caches each body in a module-level `Map`, returns `{ contentType, body }` with `contentType` from the registry (`index.html` → `text/html; charset=utf-8`, `app.js` → `text/javascript; charset=utf-8`, `styles.css` → `text/css; charset=utf-8`).
  - `export async function serveUi(request: Request): Promise<Response | undefined>`
    — `GET`/`HEAD` only (any other method → `undefined`); `uiAssetName(new URL(request.url).pathname)`; `undefined` when the path is not a UI path; otherwise load and return `200` with the asset's `content-type` and `cache-control: no-store` (HEAD: same headers, empty body). A known asset whose file cannot be read is a **server fault**: throw `new FactoryError('UI_ASSET_UNAVAILABLE', …)`.
- Consumes: `FactoryError` (`src/factory/domain/errors.ts`).
